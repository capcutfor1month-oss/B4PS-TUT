## Method notes

- All source screenshots are the pre-extracted PNGs in `extracted/` (original PDF resolution, no re-extraction performed).
- Several source PNGs still contained the *original* reference arrow baked in by the source PDF (despite being named/described as arrow-free). Where present, that arrow's pixel bounding box was detected programmatically (red-pixel thresholding + row-gap clustering in PIL/NumPy) and used as a rigorous anchor for where the new PowerPoint-native red box should sit, per the box positions listed above. Where no arrow was present (Unread toggle in p4_img0, workspace row in p3_img3), the target was located by 2x/3x zoomed pixel inspection of the source crop and, for the workspace row, by background-brightness sampling to find the highlighted row band.
- All box/badge/picture coordinates were computed programmatically in `build_slides.py` (`Placed.box_emu`): `slide_emu = picture_offset_emu + (pixel / source_px_dimension) * picture_extent_emu`, never hand-typed/eyeballed EMU numbers.
- Two images (p1_img1 'Filters and secondary sidebar' toggle panel, p7_img1 'Drafts in sidebar' toggle panel) were cropped to their top ~150px strip before embedding, dropping the large decorative illustration panel underneath that added no information for a step callout.
- Slide 171 step 2's 'after' box enc loses the entire new left-hand navigation column (icon tab rail + expanded Favorites/Workspaces/Discussions panel) as a single region, rather than separately outlining the tab-rail vs. the secondary-sidebar sub-regions -- the two are visually contiguous in the source screenshot and a single box reads more clearly on a tutorial slide.
- Layout: slides 171/172 use a 2x2 grid of steps (badge + caption at top of each cell, screenshot(s) below); slide 173 uses a simpler 1-column x 2-row layout since it only has 2 steps.
- XML for every new slide was validated with `xml.etree.ElementTree.fromstring` immediately after generation (see build_slides.py), and the rebuilt .pptx was additionally re-opened with python-pptx as a second, independent validation pass (173 slides confirmed).
- Preview PNGs (`preview_slide_171/172/173.png`) were composited in PIL using the exact same `preview_ops` list that produced the XML shapes -- same EMU coordinates, same scale factor -- so what you see in the previews is pixel-proportionally what PowerPoint will render (fonts/exact logo art are approximated since PowerPoint itself was not available to rasterize).
