# Change Specification — Documentation Intelligence, Slice 3 (Controlled PPT Mutation Handoff)

Written **before** implementation, per this repository's established convention (Slice 1's Build 1 retroactive-spec deviation, Slice 2's spec-first correction). Slice 3 is the last capability needed before the founder's first real PPT update test: given one already-approved replacement text and one already-resolved structural target (as Slice 2 already knows how to find), safely produce a new `.pptx` by reusing the existing Safe PPT Engine's own mutation primitive — nothing more.

## Classification

- **Base tier: Standard.** Rationale: this slice writes a file for the first time in the Documentation Intelligence line, but every actual write, validation, and atomic-publish mechanism it uses is the existing, already-audited Safe PPT Engine `set_shape_text()` — unmodified. This slice itself adds no new write mechanism, only a thin, bounded precondition/verification wrapper around one already-safe call. Not Trivial (genuine new guard/verification logic). Does not meet the High bar (no auth, payments, secrets, tenant isolation, or production migration — the one real production file this slice touches, the real MasterSlide deck, is only ever read, never the mutation target of any test; see "Approved user journey").
- **Applicable specialized evidence profile: neither applies.**
  - **UI-sensitive: not applicable.** No user-facing flow of its own.
  - **Data-sensitive: not applicable.** No schema, no migration, no bulk write, no batch mutation (locked out by founder instruction). A single, explicitly-targeted, already-audited mutation primitive, called once per invocation.
- **Independent-audit requirement**: consistent with every prior round, an independent Codex audit of this local diff is the required next action before any commit/push/PR/merge. Audit 1: **FAIL** (DI-S3-01, DI-S3-02, GOV-DI3-01), fixed as Repair Round 1. Re-audit 1: **FAIL/PARTIAL** — DI-S3-01 and GOV-DI3-01 confirmed closed; DI-S3-02 found PARTIAL (an output-ownership race), fixed as Repair Round 2, this record. See "Repair findings" below and `audit-report.md`. This change has not yet passed an audit.

## Approved user journey

A caller already has: (1) an already-approved replacement text (assumed correct — this slice never judges it); (2) an exact structural target (`slide_index`, `shape_index`, optionally `shape_id` as a guard) — typically Slice 2's own `LocateResult` for the corresponding existing-documentation text; (3) a source `.pptx` path; (4) a distinct output `.pptx` path. This slice answers exactly one question: "given this exact approved text and this exact target, can we safely produce the updated PPT?" It verifies the target still matches what the caller expects, applies the one mutation via the existing engine, reopens and verifies the result (including that nothing outside the target changed), and returns a deterministic report. It never decides *what* the replacement text should be, never re-locates a target if the structure has drifted, and never writes to Editorial Memory.

**Founder-preview scope**: this slice's own tests operate only against disposable fixture copies of the real MasterSlide deck (never the deck itself as a mutation target — it is read-only source material for fixture copies and, unmodified, for Slice 2's own regression). The actual founder-facing generated PPT (the real "first test") is explicitly deferred to after this slice passes independent Codex audit and integration, per direct instruction — this record does not claim that test has happened.

## Functional requirements

- `documentation_intelligence.mutate.apply_approved_replacement(source_deck_path: str, output_deck_path: str, slide_index: int, shape_index: int, replacement_text: str, shape_id: Optional[int] = None) -> MutationResult` — the slice's one entry point.
- **Target guard, before any mutation**: the exact shape at `(slide_index, shape_index)` in `source_deck_path` is resolved via the existing, unmodified `inspect_deck()` (never a second deck-parsing mechanism). Out-of-range `slide_index`/`shape_index` raises the Safe PPT Engine's own `MutationError`, reused unmodified, with the same wording its own `_resolve_shape()` already uses. If `shape_id` is supplied, it is compared against the resolved shape's actual `shape_id`; a mismatch raises a new, narrow `ShapeIdMismatchError` (a `MutationError` subclass) — the guard exists precisely so this slice never guesses or silently retargets when the deck's structure has drifted since the target was resolved (by Slice 2 or otherwise).
- **Mutation**: exactly one call to the existing, unmodified `set_shape_text(source_deck_path, output_deck_path, slide_index, shape_index, replacement_text, overwrite=False)`. `overwrite` is hardcoded `False` — this slice never overwrites an existing output path (or the source), matching "first founder test should produce a separate output `.pptx`"; a caller who deliberately wants to reuse an output path is out of this slice's bounded scope. No second text-mutation code path exists anywhere in this module.
- **Post-mutation verification, beyond what `set_shape_text` already does internally (Repair Round 1, DI-S3-01)**: `set_shape_text()` already reopens and validates (matching slide count, matching target text) before it will publish at all, and separately re-verifies the source's own hash is unchanged before publishing. This slice adds a structurally complete check on top, using only the already-reused `inspect_deck()`, via `_verify_mutation()`: total slide count equality; per-slide shape count equality; per-slide shape-id sequence identity (stable correspondence, checked before any content comparison); the target shape's text checked exactly against `replacement_text`; every other shape's text checked exactly against its pre-mutation value. No step uses a bare `zip()` over possibly-unequal-length sequences — every count is checked explicitly first, so a removed trailing shape or slide can never silently escape detection. Any discrepancy raises the Safe PPT Engine's own `ValidationError` (reused, unmodified). A successful call therefore guarantees, structurally: identical slide/shape counts and identities, the target shape holding exactly `replacement_text`, and every other shape's text byte-identical to the source.
- **Cleanup on verification failure, tied to artifact identity (Repair Round 1 + Round 2, DI-S3-02)**: `set_shape_text()` publishes its output before this slice's own verification above ever runs. If that verification fails, the file currently at `output_deck_path` is removed before the verification error propagates — but only if it is still, by POSIX device+inode identity (captured immediately after `set_shape_text()` returns, re-checked immediately before removal), the exact file this call itself published. A file that has since replaced it at that pathname (Codex Re-audit 1's ownership-race finding) is left completely untouched. The source is never touched by this cleanup. If the cleanup removal itself fails, a new `OutputCleanupError` (a `MutationError` subclass) is raised, chained onto the original verification error via `raise ... from`, so both failure contexts are preserved.
- **Zero Editorial Memory access**: this function takes no `EditorialMemory` handle and performs no retrieval or write of any kind.
- **Zero Documentation Intelligence Slice 2 involvement**: this module never imports `documentation_intelligence.locate` — no re-location, no fuzzy recovery, no "try to find it somewhere else" fallback if the exact target doesn't match. A caller who wants to re-resolve a target must do so explicitly, themselves, as a separate step.
- **Import identity**: reuses the existing `_safe_ppt_engine_import.py` bridge (Slice 2), extended to also re-export `set_shape_text`, `MutationError`, and `ValidationError` from the same single cached Safe PPT Engine module load. No new bridge, no new import mechanism.

## Non-goals (locked boundary, per founder instruction)

No redesign of Architecture v0.1; no general automation/orchestration framework; no batch mutation (exactly one shape per call); no claim extraction; no fuzzy/semantic matching of any kind (the target is exact coordinates only, never re-derived from text); no LLM reasoning; no change to Editorial Memory lifecycle behavior; no judgment about whether `replacement_text` is correct (assumed already human-approved); no second mutation mechanism alongside `set_shape_text`; no automatic re-targeting via Slice 2 or any other means when the guard fails.

## Failure and empty states

`DeckSourceError` (reused, unmodified) — a missing/invalid `source_deck_path`. `MutationError` (reused, unmodified) — `slide_index`/`shape_index` out of range, or a shape with no text frame. `ShapeIdMismatchError` (new, this module, a `MutationError` subclass) — the caller-supplied `shape_id` guard does not match the shape actually found at `(slide_index, shape_index)`; this is the explicit "do not guess or retarget" failure path. `ValidationError` (reused, unmodified) — either `set_shape_text()`'s own internal reopen/content check fails, or this slice's own `_verify_mutation()` finds any discrepancy (slide/shape count, shape identity, target text, or unrelated content). `OutputCleanupError` (new, this module, Repair Round 1, a `MutationError` subclass) — this slice's own post-mutation verification failed *and* the subsequent removal of the newly-created output also failed; the original verification error is preserved as this exception's `__cause__`. `OutputPathError` / `TransactionIOError` (reused, unmodified, from `set_shape_text()`'s own existing contract) — an unsafe or colliding output path, or a filesystem/library I/O failure during the transaction.

## Repair findings

Independent Codex Audit 1 of Build 1 returned **FAIL**, finding 2 code-level defects and 1 governance defect, fixed in Repair Round 1:

1. **DI-S3-01 (structurally incomplete post-mutation verification)**: the original verification used a single `zip()` per slide, which silently truncates to the shorter sequence — a trailing shape or trailing slide disappearing would never surface, and the target's own resulting text was never explicitly checked against `replacement_text`. **Fixed**: `_verify_mutation()` rewritten with explicit slide-count, shape-count, shape-identity, target-text, and non-target-text checks, in that order, none of them via a length-mismatched `zip()`. 6 new adversarial regressions added.
2. **DI-S3-02 (failed wrapper validation leaves published output behind)**: `set_shape_text()` publishes before this slice's own verification runs, so a verification failure previously left a real, unverified `.pptx` on disk. **Fixed (Round 1 version, later found PARTIAL — see below)**: the newly-created output was removed on a verification failure whenever the output path had not existed before the call; `OutputCleanupError` (chained onto the original failure) raised if that removal itself failed. 4 new regressions added.
3. **GOV-DI3-01 (canonical evidence records missing)**: `verification-report.md`/`audit-report.md` did not exist. **Fixed**: both added, recording the truthful build → initial-pass → audit(FAIL) → repair → validation chronology.

Independent Codex Re-audit 1 of Repair Round 1's diff confirmed DI-S3-01 and GOV-DI3-01 closed, and found DI-S3-02 still **PARTIAL**:

4. **DI-S3-02 residual (output-ownership race)**: Round 1's cleanup logic only checked whether the output path had existed *before* the call — it removed whatever currently occupied that pathname on a verification failure, regardless of whether that file was still the one this call itself created. Codex reproduced: `set_shape_text()` publishes → another process atomically replaces `output_deck_path` during verification → verification fails → cleanup deletes the replacement. **Fixed (Repair Round 2, this record)**: cleanup now compares the POSIX device+inode identity of the current occupant of `output_deck_path` against the identity captured immediately after `set_shape_text()` published, and only removes it on a match. 2 new regressions added (ownership-race case; positive-control case proving ordinary cleanup still works).
