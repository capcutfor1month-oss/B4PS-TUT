# Change Specification — Documentation Intelligence, Slice 2 (Existing Documentation Text Locator)

This file is the canonical classification record required by `docs/TESTING.md` → "Canonical recording surface," written **before** implementation this round — correcting the process-deviation pattern Slice 1's Build 1 had (OpenSpec records written retroactively, itself an Audit 1 finding). Slice 2 is a small, bounded, read-only follow-on to Documentation Intelligence Slice 1 (integrated, `main` commit `55e96f6c7d1e2cafd8210a4fb360fdec34eb9d0d`), approved by the founder as: given one target `.pptx` and one already-known existing-documentation text string, deterministically locate that text's slide/shape in the deck, or report unresolved. No PPT modification, no replacement-content decision, no Editorial Memory write, no claim extraction, no fuzzy/semantic matching.

## Classification

Not Trivial (genuine new deterministic-matching behavior, not a copy/comment/refactor); does not meet the High bar (no auth, payments, secrets, tenant isolation, or migration — this slice performs zero writes of any kind to any file, including the `.pptx` it reads).
- **Applicable specialized evidence profile: neither applies.**
  - **UI-sensitive: not applicable.** No user-facing flow of its own — a library function returning a data structure.
  - **Data-sensitive: not applicable.** No schema, no migration, no write path of any kind — `locate_documentation_text()` never calls a Safe PPT Engine mutation primitive and never touches Editorial Memory.
- **Independent-audit requirement**: consistent with every prior round in this repository, an independent Codex audit of this local diff is the required next action before any commit/push/PR/merge. Initial Codex audit: **FAIL** (DI-S2-01, DI-S2-02, GOV-DI2-01 — see "Repair Round 1 findings" below and `audit-report.md`). This change has not yet passed an audit.

## Approved user journey

A caller (a human, or a later slice) already has one known existing-documentation text string — for example a documentation-type `KnowledgeState.content` already retrieved from Editorial Memory via Slice 1, or any other pre-known string — and one target `.pptx` path. `locate_documentation_text()` inspects that deck's real structure via the unmodified Safe PPT Engine `inspect_deck()`, and returns either exactly one matched structural target (slide/shape) or an explicit unresolved result with a reason. Approved **product** Knowledge content never participates in this lookup — it is a separate concept (what should eventually replace the documentation, decided by a human, not this slice) from where the *existing* documentation wording currently lives.

## Functional requirements

- `documentation_intelligence.locate.locate_documentation_text(deck_path: str, documentation_text: str) -> LocateResult` — the slice's one entry point.
- **Deck inspection**: via the existing, unmodified `inspect_deck()` from `baseline/B4PS-TUT-main/.b4ps-tools/lib/ppt_engine.py` (the repository's one real Safe PPT Engine implementation — confirmed by `git log` as the actively-built-and-audited location, not merely a frozen baseline copy). No new deck-parsing logic of any kind is added; this slice only filters/matches over `inspect_deck()`'s own existing per-slide, per-shape `text`/`slide_index`/`shape_index`/`shape_id` fields.
- **Blank-query rejection, before any matching (Repair Round 1, DI-S2-01)**: if `documentation_text`'s whitespace-normalized value is empty, the function returns `status="unresolved"`, `unresolved_reason="no_match"` immediately, before the candidate-matching loop ever runs — deterministically, every time, regardless of what any shape's text is (including an equally blank shape). A bad `deck_path` is still surfaced as its own typed error either way; this check only ever suppresses a *match*, never the underlying deck-read error.
- **Matching, per shape, in priority order** (a shape earns at most one basis — the first that applies; only reached once the blank-query rejection above has passed):
  1. `"exact"` — shape text equals `documentation_text` exactly (no normalization).
  2. `"whitespace_normalized"` — both sides whitespace-normalized (runs of whitespace collapsed, ends stripped) are equal.
  3. `"bounded_substring"` — the whitespace-normalized `documentation_text` is a substring of the whitespace-normalized shape text, or vice versa (both sides non-empty after normalization — an empty normalized string is never treated as matching or matched-into).
- **Ambiguity is conservative, by shape count, not by rule**: every shape that earns any basis above is one candidate, counted once. Zero candidates anywhere in the deck → `status="unresolved"`, `unresolved_reason="no_match"`. Two or more candidates (regardless of which rule(s) matched each) → `status="unresolved"`, `unresolved_reason="ambiguous_multiple_matches"`. Exactly one candidate → `status="matched"`, carrying that shape's `slide_index`, `shape_index`, `shape_id`, actual `text` as `matched_text`, and its earned `match_basis`.
- **Product Knowledge plays no role**: this function takes no Editorial Memory handle, no product key, and performs no retrieval of any kind — it is a pure function of `(deck_path, documentation_text)`.
- **Zero writes**: no Safe PPT Engine mutation primitive (`set_shape_text`, `move_shape`, `resize_shape`, `set_shape_geometry`, `replace_picture`) is called or imported by name anywhere in this module.
- **Errors propagate typed, unmodified**: `inspect_deck()`'s own typed `SafeDeckError` subclasses (e.g. `DeckSourceError` for a missing/invalid `.pptx`) are raised through unchanged — a bad deck path is a caller/reference error, not a "no match" result, matching Slice 1's existing convention of propagating typed errors from the systems it reuses rather than swallowing them.
- **Import identity**: a bridge module, `_safe_ppt_engine_import.py`, loads `ppt_engine.py` via `importlib.util.spec_from_file_location` under a fixed private module name, cached in `sys.modules` so repeated calls within one process reuse the same loaded module. `ppt_engine.py` itself has no internal package-relative imports (verified: only stdlib + `PIL` + `pptx`), so this bridge never needs to claim, and never writes to, `sys.modules["lib"]` for its own private load. **Repair Round 1 (DI-S2-02)**: before doing that private load, the bridge now checks, read-only, whether the Safe PPT Engine's own established `from lib import ppt_engine` path (used by `.b4ps-tools/tests/`) has already loaded the exact same file under `sys.modules["lib"].ppt_engine`, and reuses it if so — closing the ordering where that established path runs first. The reverse ordering (this bridge runs first, the established path runs second) is not safely closable without this bridge claiming `sys.modules["lib"]` preemptively, which would risk breaking `editorial-memory/lib`'s own equally-legitimate claim on that same name in the same process — reported, not fixed; see "Failure and empty states".

## Non-goals (locked boundary, per founder approval)

No PPT mutation of any kind; no replacement-text/what-should-it-say decision; no Editorial Memory write of any kind; no extraction of claims from an entire deck (only the one caller-supplied string is searched for); no semantic product-vs-documentation reasoning (that remains Slice 1's own, separately-bounded job — this slice never reads product Knowledge at all); no fuzzy/embeddings/LLM matching; no new Safe PPT Engine capability of any kind (only the existing `inspect_deck()` is called, unmodified).

## Failure and empty states

`DeckSourceError` (and any other `SafeDeckError` subclass `inspect_deck()` itself may raise) — propagated unmodified for a missing, empty, or invalid `.pptx`. `LocateResult(status="unresolved", unresolved_reason="no_match")` — no shape anywhere in the deck matches by any rule. `LocateResult(status="unresolved", unresolved_reason="ambiguous_multiple_matches")` — two or more shapes match (whether by the same or different rules); never resolved by picking one.

**Residual limitation, documented not fixed (Repair Round 1, DI-S2-02 order B — reported per explicit instruction, not force-closed)**: `baseline/B4PS-TUT-main/.b4ps-tools/lib/` is itself a real, separately-existing Python package also named `lib` (used by that tree's own test suite via `from lib import ppt_engine`), the same bare name `editorial-memory/lib` uses. This bridge safely converges with that established path when it already ran first (read-only detection of `sys.modules["lib"].ppt_engine`). When this bridge's own private load runs *first* instead, and the established path runs afterward in the same process, the two do **not** converge — two independently-correct, non-`is`-identical module objects for the same physical file, verified non-corrupting by regression (`test_ppt_engine_import_order.py`). Closing this direction would require this bridge to claim `sys.modules["lib"]` for `.b4ps-tools/lib` before knowing whether the process will ever need it — but `editorial-memory/lib` also only ever wants to own that exact name, and every normal `documentation-intelligence/tests/` run already loads both bridges in the same process, so a preemptive claim here would break Slice 1 the moment `.b4ps-tools` also happened to be on `sys.path`. This is a repository-wide package-ownership question, not a defect this slice is authorized to redesign its way out of.

## Repair Round 1 findings (this record)

Independent Codex audit of Slice 2's Build 1 returned **FAIL**, finding 3 defects, fixed/addressed in this same repair round:

1. **DI-S2-01 (blank documentation query)**: an empty or whitespace-only `documentation_text` could exact/whitespace-match an equally blank shape, producing a false `status="matched"`. **Fixed**: rejected as `unresolved`/`no_match` before any candidate matching, unconditionally.
2. **DI-S2-02 (Safe PPT Engine module/type identity)**: the bridge could produce a duplicate, non-identical `ppt_engine.py` module when the engine's own established `from lib import ppt_engine` path had already loaded it. **Fixed for order A** (established path first): read-only reuse of the already-loaded module via `sys.modules["lib"].ppt_engine`. **Order B (this bridge first) reported, not fixed**: architecturally unclosable without claiming `sys.modules["lib"]` preemptively, which would collide with `editorial-memory/lib`'s own legitimate claim on the same name in the same process — see "Failure and empty states" above and `audit-report.md`.
3. **GOV-DI2-01 (canonical verification/audit evidence)**: `verification-report.md` and `audit-report.md` were missing. **Fixed**: both added, recording the truthful build → audit(FAIL) → repair → validation chronology.
