## PROJ-007 — Safe PPT Engine Build 1

**Decision:** Built the first Safe PPT Engine layer at `baseline/B4PS-TUT-main/.b4ps-tools/lib/ppt_engine.py`, using `python-pptx` (added to `requirements.txt`) rather than extending the baseline's existing hand-rolled XML-surgery approach in `lib/deck.py` — the two serve different purposes (`deck.py` is a purpose-built, high-performance surgical writer scoped to the two known production decks and their known shape conventions; the engine needs to safely load and describe *any* explicit `.pptx` path generically, which `python-pptx` already does safely and correctly). The engine provides: `load_deck` (typed, never-fallback loading), `inspect_deck` (deterministic structural JSON with no semantic interpretation), `create_working_copy` (mutation always staged off both the original and the final output path), and `set_shape_text` (the one controlled mutation primitive built this pass — explicit `(slide_index, shape_index)` targeting only, validated by reopening the saved result before it is placed at the caller's output path). Exposed via `engine-inspect` and `engine-set-text` CLI commands. Verified with 21 new tests (37 total) against synthetic fixtures built programmatically with `python-pptx`/`Pillow` — the 8 unavailable Git LFS assets were not touched.

**Reason:** The approved build order requires a safe, deterministic mechanical foundation (read/inspect/copy/mutate/save/validate/preserve) before any Documentation Intelligence or semantic capability can be layered on top. Establishing the pattern with one real, tested mutation primitive (text update) proves the safety invariants — source never modified, output path never collides, invalid input fails before mutation, output is reopened and content-verified after save — without yet committing to which richer primitives (move/resize/image-replace) Documentation Intelligence will actually need.

**What was deliberately not done:** no semantic shape identification, fuzzy matching, screenshot intelligence, or Documentation Intelligence; no additional mutation primitives beyond `set_shape_text`; no changes to `lib/deck.py`, `lib/plan.py`, `lib/match.py`, `lib/anchors.py`, `lib/layout.py`, or `lib/geometry.py` (existing anchor/matching workflow is untouched and independent of the new engine layer); the 8 missing LFS binaries were not obtained or fabricated; the canonical ZIP was not touched.

**Status:** Active.

## PROJ-008 — Safe PPT Engine Build 2: visual mutation primitives

**Decision:** Added four visual mutation primitives to `lib/ppt_engine.py`: `move_shape` (left/top, EMU only), `resize_shape` (width/height, EMU only), `set_shape_geometry` (left+top+width+height as one atomic operation, for future red-box relocation), and `replace_picture`. All coordinates/dimensions are EMU — python-pptx's and OOXML's own native integer unit; no other unit is accepted, and callers are responsible for converting from inches/points/pixels if needed. `move_shape` and `resize_shape` are each verified not to touch the other's attributes (a shared regression test proves resize does not move the shape, matching PowerPoint's own semantics — no repositioning side effect was observed or needed handling). `set_shape_geometry` validates all four values *before* any working copy is staged, so an invalid value cannot leave a partially-applied geometry anywhere, in memory or on disk.

`replace_picture` rejects a non-picture target shape and a missing/empty/unreadable replacement image before staging anything. Its default (and only, for this build) behavior preserves the existing shape's left/top/width/height frame exactly, regardless of the replacement image's own pixel dimensions or aspect ratio — chosen as the safest deterministic behavior, since it requires no cropping/scaling decision and matches how PowerPoint's own `blipFill` model already renders an image into a fixed frame. Implementation touches OOXML directly in exactly one place — repointing the picture's `p:blipFill/a:blip/@r:embed` relationship to a newly-added image part via python-pptx's own `SlidePart.get_or_add_image_part()` plus the `CT_Blip.rEmbed` attribute descriptor (both existing, documented python-pptx internals, not raw string/XML surgery) — isolated entirely inside `replace_picture`; no other code touches OOXML for image handling. Any existing crop data (`a:srcRect`) is preserved by construction, since it is never touched.

Build 1's final-publish step (a bare `shutil.copy2(staged, output_path)`) was not fully atomic — an interruption mid-copy could leave a partially-written file at `output_path`. Hardened this pass with `_publish_atomically()` (copy to a same-directory temp file, then `os.replace()`, which is atomic on the same filesystem) and retrofitted it onto `set_shape_text` as well as all four new primitives, per the explicit instruction to harden Build 1's atomicity within this build if it did not already guarantee it.

**Reason:** These are the specific geometry/image operations future red-box relocation and screenshot-swap work will call. Building them as small, independently-tested, deterministic primitives — reusing Build 1's staged-copy/validate/publish pattern rather than inventing a parallel one — keeps the mechanical foundation trustworthy before any semantic targeting is layered on top of it.

**What was deliberately not done:** no semantic shape identification, fuzzy matching, screenshot intelligence, automatic affected-slide detection, Editorial Memory, or Documentation Intelligence; no rotation/flip or other geometry attributes beyond left/top/width/height; no shape creation/deletion; no automatic aspect-ratio cropping or aesthetic image adjustment; no changes to `lib/deck.py`, `lib/plan.py`, `lib/match.py`, `lib/anchors.py`, `lib/layout.py`, or `lib/geometry.py`; the 8 missing LFS binaries (including both production decks) were not obtained, fabricated, or needed by any test; the canonical ZIP was not touched.

**Status:** Active.

## PROJ-009 — Safe PPT Engine Audit Repair 1 (Codex findings F-01–F-08)

**Decision:** An independent Codex audit of Safe PPT Engine Builds 1–2 found 8 defects. All 8 are fixed in `lib/ppt_engine.py`/`b4ps.py`, per-finding:

- **F-01 (critical, source aliasing):** `_assert_safe_output_path` now compares `os.path.realpath` of both paths (resolves symlinks even when the output's final path component does not yet exist) and, when both paths currently exist, additionally checks `os.path.samefile` (catches hardlinks/bind-mount aliasing realpath alone can miss). Applies uniformly to `set_shape_text`, `move_shape`, `resize_shape`, `set_shape_geometry`, and `replace_picture` (all route through this one function). The pre-existing before/after source-hash check is kept as defense-in-depth, not the primary protection.
- **F-02 (high, no-overwrite publication race):** `_publish_atomically` now branches on `overwrite`. `overwrite=False` opens the destination itself with `os.O_CREAT | os.O_EXCL`, which atomically fails if anything exists there at that instant — no separate exists-check followed by a write. `overwrite=True` keeps the prior same-directory-temp-file + `os.replace` atomic-rename approach.
- **F-03 (high, raw filesystem errors leak):** every mutation primitive now calls `load_deck(input_path)` (the typed validation boundary) before `file_sha256`/staging, via a shared `_validate_and_hash_source` helper. A missing input now raises `DeckSourceError`, never a bare `FileNotFoundError`. Verified at both the engine API and CLI boundary (all 5 mutation CLI commands exit 1 with a clean `error:` message, no traceback, for missing/empty/corrupt input).
- **F-04 (medium, stale media left in package):** `replace_picture` captures the old relationship id before repointing the blip, then calls `_drop_relationship_if_unreferenced`, which scans the slide's shape tree for any remaining `a:blip` still using that id and only then drops the relationship. python-pptx's own package writer serializes only parts still reachable via some relationship, so an unreferenced image part is automatically absent from the next save with no separate manual part-deletion step. Verified against actual ZIP package contents (not just API-level state): single-picture replacement removes the old media file; two pictures on one slide sharing the same image (python-pptx assigns them the same relationship id automatically) — replacing one leaves the other's image completely intact.
- **F-05 (medium, staging/failure cleanup gaps):** `create_working_copy` now wraps `shutil.copy2` in try/except, removing the allocated temp path and raising `DeckSourceError` on any copy failure. Failure injection tests cover all four transaction points (staging copy, save, validation, publication) and confirm: source untouched, no partial/incorrect final destination, no leaked `b4ps_engine_*`/`.b4ps_publish_*` temp file, typed error where applicable.
- **F-06 (medium, missing verification records):** this decision entry plus `openspec/changes/safe-ppt-engine/verification-report.md`, recording Builds 1–2 and this repair's classification, rationale, applicable profiles, commands, results, limitations, and — critically — that Builds 1–2 were marked complete *before* independent audit and *failed* that audit; re-audit of this repair is still required and has not happened.
- **F-07 (low, non-picture target validated after staging):** `replace_picture` now calls `_preflight_resolve_shape` (a throwaway `load_deck` against the original input) and checks `shape_type` before `create_working_copy` is ever called, so an invalid target creates no temp file. The same preflight-resolve pattern was applied uniformly to `set_shape_text` and the shared geometry-mutation path too, as a direct, minimal implementation of the cross-cutting contract's stated order ("validate source + target + path safety" before "stage privately") rather than a change scoped to F-07 alone.
- **F-08 (low, canonical inspection includes absolute path):** `inspect_deck`'s return value no longer includes a `path` key, so two byte-identical `.pptx` files at different filesystem paths now produce an equal result. A new `describe_deck(path)` wraps it as `{"source_path": ..., "structure": inspect_deck(path)}` for callers that want provenance; `engine-inspect`'s CLI/JSON output now uses `describe_deck`, so its JSON shape changed from a flat dict to this nested form (documented, deliberate, and covered by updated CLI tests).

48 new adversarial/fault-injection tests added (`tests/test_ppt_engine_audit_repair.py`), 120 total in the suite. Two pre-existing tests were updated, each with an explicit reason: one `OutputPathError` message-wording assertion (F-01 improved the message text) and the CLI JSON-shape assertions in `test_engine_cli.py`/`test_engine_cli_geometry_image.py` (F-08's `structure`/`source_path` split). No test was weakened; all 72 pre-existing behavioral assertions still hold.

**Reason:** These are safety-critical defects in the exact guarantees the Safe PPT Engine exists to provide before any semantic/AI layer is built on top of it. Fixing them now, with adversarial regression coverage proving each fix, keeps the mechanical foundation trustworthy rather than deferring known gaps into Documentation Intelligence work that would inherit them.

**What was deliberately not done:** no redesign of Architecture v0.1; no product-scope expansion; no Editorial Memory or Documentation Intelligence work; no attempt to obtain or fabricate the 8 missing production LFS binaries; no refactor of `lib/deck.py`, `lib/plan.py`, `lib/match.py`, `lib/anchors.py`, `lib/layout.py`, or `lib/geometry.py` (unrelated baseline modules, untouched); the canonical ZIP was not touched. Independent Codex re-audit of this repair was **not** performed as part of this decision — that is the explicitly required next action, not something Claude can self-certify.

**Status:** Active. Re-audit pending.

## PROJ-010 — Safe PPT Engine Audit Repair 2 (re-audit findings F-02, F-04, F-05, F-06, R-01, R-02)

**Decision:** An independent Codex re-audit of Audit Repair 1 confirmed F-01, F-03, F-07, and F-08 correctly closed (no regression), and found 6 findings remaining. All 6 are fixed:

- **F-02 (high, no-overwrite publication not fully atomic):** `_publish_atomically` no longer opens the final `output_path` directly at all for `overwrite=False`. It now writes the complete staged content to a same-directory temp file, flushes and `os.fsync`s it, then publishes via `os.link(tmp, output_path)` - an atomic hard-link create that fails with `FileExistsError` (converted to `OutputPathError`) if the destination already exists, without the destination ever being observable as a partial file (unlike the prior `O_CREAT|O_EXCL` stream, which created the destination filename before any bytes were written into it). The temp file is removed in both the success and failure case. `overwrite=True` is unchanged (atomic `os.replace`).
- **R-01 (high, source-integrity check ran after publication):** a new shared `_finalize_transaction` helper is now the only path to `_publish_atomically` for every mutation primitive: it re-checks the source hash **before** calling `_publish_atomically` (the actual gate - if the source changed, publication is never attempted) and, only as defense-in-depth, once more after. A test asserts the literal call order (`_finalize_transaction` before `_publish_atomically`) for all four geometry/text mutation families, and separate tests prove a tampered source blocks publication entirely, leaving no output and no leaked temp files.
- **F-05 (medium, transaction I/O errors could leak as raw OSError):** a new `TransactionIOError` type normalizes filesystem/library failures during working-copy creation (`create_working_copy`), save (`_save_staged`, used by all three mutation code paths), temp-output preparation, and publication. Writing the adversarial test for this surfaced a genuine, previously-unwrapped bug: `_publish_atomically`'s own `tempfile.mkstemp` call was not inside any try/except, so a permission-denied output directory produced a raw traceback through the CLI - found via a real (unmocked) read-only-directory test, not a mock, and fixed by wrapping that call too.
- **F-04 (medium, relationship cleanup only scanned spTree):** `_drop_relationship_if_unreferenced` now scans `slide._element.iter(qn("a:blip"))` - the entire `<p:sld>` XML tree - instead of only `slide._element.spTree`. This correctly preserves a relationship still used by the slide background (`p:cSld/p:bg/p:bgPr/a:blipFill/a:blip`, a sibling of `p:spTree`, not a descendant of it) or any other non-shape slide element. Verified with a fixture where a foreground picture and the slide background share one relationship id (python-pptx's own default behavior when the same image content is related to the same slide part twice) - replacing the foreground picture leaves the background's relationship and media completely intact, which the prior spTree-only scan would have incorrectly dropped. A crop-preservation regression test (`crop_left`/`crop_top`/`crop_right`/`crop_bottom` before and after replacement) was added alongside it.
- **F-06 (medium, verification/governance evidence incomplete):** added `openspec/changes/safe-ppt-engine/spec.md` - the canonical classification record (base tier, rationale, applicable profiles, explicit audit requirement) `docs/TESTING.md` → "Canonical recording surface" requires live in the change's `spec.md`, not only `verification-report.md`, which was the actual gap. Expanded `verification-report.md` with builder review, founder-preview status (recorded truthfully as **pending** - no human has previewed a generated `.pptx` in real PowerPoint - not fabricated as complete), the Data-sensitive profile's specific gates (migration test and tenancy-isolation N/A with stated reasons; data-preservation and rollback-plan evidence stated), and full commands/results. Added `openspec/changes/safe-ppt-engine/audit-report.md`, the canonical location for independent-audit findings per `docs/PIPELINE.md`, recording the complete audit history (Audit 1 FAIL → Repair 1 → Audit 2 FAIL → Repair 2 → Audit 3 pending) truthfully, without claiming any audit passed that has not.
- **R-02 (low, adversarial tests proved end-state, not mechanism):** strengthened tests to prove the actual mechanism, not just outcomes: a call-count spy on `create_working_copy` proves a non-picture target results in *zero* staging calls (F-07), not merely no leftover temp file; call-order assertions prove the R-01 integrity gate runs strictly before publish for every mutation family; the F-03 missing/empty/corrupt/valid-ZIP-but-not-PPTX matrix now runs against every mutation family (`set_shape_text`, `move_shape`, `resize_shape`, `set_shape_geometry`, `replace_picture`) at both the engine-API and CLI boundary; image-replacement coverage was extended with crop-bearing, shared-picture, and background-sharing fixtures.

65 new tests added (`tests/test_ppt_engine_audit_repair_2.py`), 185 total in the suite. Two pre-existing tests updated with explicit justification (both now assert `TransactionIOError`, the more specific type F-05 introduces, in place of the broader error type they previously accepted) - no test was weakened; explicit regression tests confirm F-01/F-03/F-07/F-08 remain closed.

**Reason:** These were exactly the gaps a second independent audit round exists to catch - a mostly-correct first repair with residual atomicity, sequencing, error-typing, and cleanup-scope defects, plus genuinely incomplete governance recordkeeping. Fixing them, with tests that prove the mechanism rather than only the outcome, keeps the mechanical foundation trustworthy before any further capability is built on it.

**What was deliberately not done:** no redesign of Architecture v0.1; no product-scope expansion; no Editorial Memory or Documentation Intelligence work; no attempt to obtain or fabricate the 8 missing production LFS binaries; no refactor of `lib/deck.py`, `lib/plan.py`, `lib/match.py`, `lib/anchors.py`, `lib/layout.py`, or `lib/geometry.py`; the canonical ZIP was not touched; no founder approval or independent-audit-pass was fabricated - both the founder-preview and the Audit 3 re-audit gates are recorded as genuinely pending.

**Status:** Active. Subsequently re-audited (Audit 3); see PROJ-011.

## PROJ-011 — Safe PPT Engine Audit Repair 3 (Audit 3 findings F-05, F-06, R-01, R-02) — local only, not merged

**Decision:** An independent Codex re-audit of Audit Repair 2 (Audit 3, against merged commit `69bb4761921ac7f7b843beb04ab255a2b272865e`) confirmed F-01, F-02, F-03, F-04, F-07, and F-08 correctly closed with no regression, and found 4 findings remaining. Per explicit task instruction, all 4 are fixed as **local, uncommitted working-tree changes only** - not committed, pushed, or opened as a PR, so `main` is unaffected by this decision and still reflects Audit Repair 2.

- **F-05 (wrap `create_working_copy`/`mkstemp` and cleanup failures; cleanup failure must not be silently swallowed):** `create_working_copy` now wraps its `tempfile.mkstemp` call (previously unwrapped) as well as the `shutil.copy2` call in typed-error handling. A new `_remove_reporting_failure(path)` helper replaces the previous `_safe_remove`, which discarded cleanup `OSError`s with a bare `pass`; the new helper never itself raises, but returns a description of any removal failure, which every caller folds into the error it is already raising (or, when nothing else is failing, raises on its own). A new `_staged_copy` context manager centralizes the create/cleanup pairing for every mutation primitive: if the wrapped mutation raised, a cleanup failure is reported as a stderr warning (visible, but not replacing the primary exception's type); if the wrapped mutation succeeded, a cleanup failure is itself raised as `TransactionIOError`, since a leaked temp file is then the only remaining problem and must not be silently accepted as success. The same reporting-not-swallowing treatment was applied to every cleanup call site inside `_publish_atomically`.
- **R-01 (source integrity must be checked immediately before publication; remove the post-publication check as a failure gate; source deletion/read errors during the pre-publish check must be typed; once atomic publication succeeds, the transaction is successful):** `_finalize_transaction` now calls a new `_verify_source_hash_or_raise(input_path, before_hash)` exactly once, immediately before `_publish_atomically`, and nothing after it. The previous second hash comparison that ran *after* `_publish_atomically` returned - the "defense-in-depth" check from Audit Repair 2 - has been removed entirely, per explicit instruction that it must not remain a failure gate: once publication succeeds, the transaction is complete, and re-checking afterward could only produce a confusing partial-success-that-raises state, never actually protect anything (the publish had already happened). `_verify_source_hash_or_raise` itself now distinguishes a source that is unreadable/deleted (typed `DeckSourceError`, since that is a read failure, not a content mismatch) from a source that is readable but has changed (typed `SafeDeckError`, the existing safety-invariant-violation case) - previously, `file_sha256` could raise a bare `OSError` at this exact point if the source vanished between the initial hash and this check.
- **R-02 (add regressions for the exact residual cases above):** 19 new local tests (`tests/test_ppt_engine_audit_3.py`) cover: `mkstemp` failure during both staging and publication; a cleanup failure that is itself induced (via mocking `os.remove`) on both the "mutation also failed" path (proving the secondary failure is reported, not substituted for the primary exception type) and the "mutation succeeded" path (proving the cleanup failure becomes the reported outcome, not silently accepted); source deletion and source tampering exactly at the pre-publish integrity boundary, parametrized across every mutation family (`set_shape_text`, `move_shape`, `resize_shape`, `set_shape_geometry`) plus a dedicated pair of tests proving `replace_picture` goes through the identical single integrity gate; and a call-order assertion proving the integrity check runs exactly once, immediately before (never after) `_publish_atomically`. All 185 pre-existing tests pass unmodified (204 total).

Governance recordkeeping (F-06) was also corrected this round, per explicit instruction: `spec.md` now states outright, under a "Process deviation" heading, that its classification was written retroactively (after Builds 1-2 were already implemented and merged) rather than presenting it as though it happened at the normal pre-implementation time; no approval is invented anywhere in `spec.md`'s "Approval" section (still truthfully "Not approved - no founder sign-off has occurred"); `verification-report.md` now states the *actual* recorded CI result for the last pushed round (Audit Repair 2 / PR #7: GitHub Actions `validate` passed, confirmed via `gh pr checks` and the merge-commit run) in place of the prior placeholder "expected to pass... updated once inspected" language that was never actually updated; `audit-report.md`'s verdict table now includes Audit 3's actual result and a fourth (not-yet-performed) row for Audit 4; and founder-preview status remains explicitly recorded as pending in both files, unchanged by this round.

**Reason:** A third independent audit round finding a narrower but still real set of defects (a silently-discarded cleanup failure that could mask data loss context, and an integrity check sequenced so a corrupted-transaction case could theoretically still report success after publication had already happened) is exactly the kind of residual risk that should not go unfixed just because two prior rounds already passed. Fixing it, and correcting the governance record to state plainly what has and has not been independently verified, keeps both the code and its paper trail honest before a fourth audit round and before any further capability is built on this engine.

**What was deliberately not done:** no commit, push, PR, or merge - these changes exist only in the local working tree, per explicit instruction, so Codex can audit them directly; no redesign of Architecture v0.1; no product-scope expansion; no Editorial Memory or Documentation Intelligence work; no attempt to obtain or fabricate the 8 missing production LFS binaries; no refactor of `lib/deck.py`, `lib/plan.py`, `lib/match.py`, `lib/anchors.py`, `lib/layout.py`, or `lib/geometry.py`; the canonical ZIP was not touched (its SHA-256 was re-verified); no founder approval or independent-audit-pass was fabricated - the founder-preview gate and the pending Audit 4 are both recorded as genuinely open.

**Status:** Active, local only. Subsequently re-audited (Audit 4, directly against this local diff — no push required); see PROJ-012.

## PROJ-016 — Editorial Memory Slice 1

**Decision:** Editorial Memory is the next approved implementation milestone in locked Architecture v0.1, per the founder's lifecycle clarification (living/evolving/version-aware/provenance-preserving/history-preserving knowledge layer) and the subsequently accepted design audit recorded in `docs/EDITORIAL_MEMORY_IMPLEMENTATION_AUDIT.md` (committed here for the first time as part of this change - it had previously existed only as local, uncommitted design work, never merged). Slice 1 - the smallest real implementation proving the lifecycle end-to-end, per explicit task instruction not to build a broad knowledge platform - is implemented, tested, and integrated.

- **Three entities, no ontology:** `Evidence` (an artifact/observation, never itself knowledge), `KnowledgeItem` (the durable subject, identified by a stable natural key), `KnowledgeState` (one versioned claim about a `KnowledgeItem`, always grounded in evidence). No graph semantics, no universal semantic IDs beyond ordinary persistence identity, no vector or graph database.
- **Core invariant enforced in code:** Evidence never promotes itself into Knowledge. `propose_state` raises typed `MissingProvenanceError` if no evidence is cited and typed `UnknownEvidenceError` if a cited evidence id doesn't exist. The only way a state becomes `current` is an explicit `approve_state` call - no evidence type, including browser observation, auto-promotes.
- **Supersession vs. invalidation kept distinct:** approving a new state moves the prior current state to `superseded` (never deleted, always traceable via `superseded_by`); `invalidate_state` is a separate operation for knowledge that was never trustworthy, requiring no replacement to exist. Both statuses remain in `get_history` forever.
- **Unresolved conflict is a first-class, minimal concept:** a proposed state whose `relation_to_previous` is `contradicts` has a computed `review_required` property (never a stored field that could drift), surfaced via `has_pending_conflict`/`get_conflicts`. The existing current state is untouched until an explicit approval resolves it - a newer, contradicting proposal never silently wins by virtue of being newer.
- **No scoring anywhere:** `evidence_quality` (`high`/`medium`/`low`) is artifact-reliability metadata, not a truth score. `get_evidence_type_summary` preserves per-state source-category counts (e.g. distinguishing "browser + maintainer + screenshot" from "browser + browser + browser") purely as information, with no ranking or automatic weighting.
- **Persistence:** plain, atomically-written (temp file + rename) JSON files under a caller-chosen directory - one file per `Evidence` record, one per `KnowledgeItem` (embedding its full append-only state history). No new dependency (Python standard library only), no database, git-diffable like the rest of this repository. `EditorialMemory` reads fresh from disk on every call rather than caching, so reload-from-storage correctness holds by construction.
- **Feature-area naming convention** (`<platform>.<feature>`, e.g. `desktop.filters`) and **optional editorial `rationale`** on proposed states, per the founder-approved amendments, both implemented as plain fields - no registry, no taxonomy.

26 new tests (`editorial-memory/tests/test_editorial_memory.py`), including one deterministic 15-step end-to-end test proving the full evidence → item → state → approval → current-retrieval → new-unapproved-evidence → supersession → contradiction/review-required flow in a single run, matching the required Slice 1 lifecycle scenario exactly. `python scripts/check_pipeline.py` passes; the Safe PPT Engine (`baseline/B4PS-TUT-main/.b4ps-tools/`) was not touched.

**Reason:** Editorial Memory exists to hold claims about Bridge4PS without ever letting an artifact's mere existence be mistaken for approved current truth - exactly the guarantee the founder's lifecycle clarification and the "knowledge system, not a truth system" framing describe. Building the smallest version that proves this end-to-end, before any broader platform work, keeps the same safety-first discipline established for the Safe PPT Engine: a mechanical, testable foundation first, semantic/AI capability only after independent audit confirms the foundation is trustworthy.

**What was deliberately not done:** no Documentation Intelligence, no AI reasoning over memory, no affected-slide detection, no semantic red-box targeting, no browser automation or live `browser_observation` producer, no vector search, no embeddings, no graph database, no ontology, no generalized Bridge4PS Product Knowledge platform, no UI, no Freshdesk/AppSheet integration, no automatic ingestion from old PPTs, and no automatic promotion of evidence into truth; no CLI (nothing calls this API yet); no purge/hard-deletion tooling (deferred per the already-approved design - normal supersession/invalidation is the only lifecycle mechanism this slice implements); no modification to Safe PPT Engine behavior; no redesign of Architecture v0.1; no Slice 2 work, per explicit instruction to stop after this slice.
